# Meu guia de aprendizado do TrainForge

Esta seção é para eu entender, operar, modificar e explicar o projeto que estou desenvolvendo. As anotações de pastas que estavam no README principal estão em [Peças do projeto](pecas-do-projeto.md), com os nomes e as responsabilidades conferidos no checkout.

| Quero conseguir… | Por onde começar | Resultado do estudo |
|---|---|---|
| Explicar as tecnologias e encontrar o código | [Peças, pastas e persistência](pecas-do-projeto.md) | Distinguir app, API, catálogo, banco, ferramentas e arquivos gerados |
| Acompanhar uma ação da tela ao banco | [Fluxo de uma ação](fluxo-de-uma-acao.md) | Localizar a tela, o estado, a chamada HTTP, a regra e o SQL |
| Abrir, acompanhar e encerrar o ambiente | [Operação local](operacao-local.md) | Usar os comandos existentes e saber o que permanece salvo |
| Ver mudanças de tela no celular na hora | [Teste ao vivo por Wi-Fi](teste-ao-vivo-wifi.md) | Parear o celular, rodar a versão de desenvolvimento e usar hot reload |
| Explicar como o projeto evoluiu | [Desenvolvimento e apresentação](desenvolvimento-e-apresentacao.md) | Relacionar decisões, entregas, evidências e limites reais |

Uma ordem prática: leia a visão das peças, acompanhe a consulta do catálogo no código e então opere o ambiente quando quiser usá-lo. Estudar os arquivos não exige iniciar serviços ou repetir o login Google. Para treinar uma explicação, use o roteiro do último guia e abra somente os diagramas necessários.

Os [diagramas](../arquitetura/diagramas/README.md) ajudam a visualizar; o [mapa técnico](../arquitetura/README.md) detalha a implementação. Para saber o que mudou e qual é a próxima entrega, consulte o [handoff vigente](../execucao/v1/handoff.md) e o [backlog](../execucao/v1/backlog.json). Estes guias ensinam o projeto; não mantêm um segundo backlog.
